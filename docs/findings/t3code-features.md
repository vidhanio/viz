# Compressed summary — ranked P0/P1 gaps

**P0 (daily-use blockers)**

1. **Stop/interrupt a running turn** — no protocol method; the only cancel path is killing the ACP process. `S`
2. **Inline approvals + permission modes** — viz auto-answers `request_permission` from config (`allow|reject`), so agents either fail silently or run unsupervised. `M`
3. **Model + reasoning-effort picker per chat** — ACP `session/new` returns `configOptions`; viz discards them and never calls `session/set_config_option`. `M`
4. **Slash commands from the agent** — `available_commands_update` is a stable ACP update viz drops; a `/` menu is nearly free. `S`
5. **Attachments (images/files) in the composer** — prompt is text-only; ACP `promptCapabilities.image`/`resource_link` unused. `L`
6. **Real tool-call detail + diffs** — viz shows title+status; ACP `tool_call.content` (`diff`, `terminal`, `locations`, `rawInput/rawOutput`) is discarded. `M`
7. **Thread identity & lifecycle** — rename, pin, archive, delete, unread; viz titles are auto-derived and the sidebar is an id-sorted flat list. `S`–`M`
8. **Command palette + search** — no palette, no thread search, no in-thread find, no older-entry paging. `M`
9. **Diff panel** — no turn/full-thread diff, file tree, per-file review, or revert. `L`

**P1 (ADE parity)** 10. **Projects + worktrees + branch toolbar** — viz has one fixed `cwd` per chat; no repo, branch, worktree, or base-branch concept. `L` 11. **Checkpoints / "edit from here" / revert files** — only pi-durable transcript checkpoints exist; no workspace snapshots. `L` 12. **Terminal drawer (server-owned PTYs)** — absent; t3 uses `node-pty`, not ACP terminals. `L` 13. **Settings UI (project/environment layering) + keybindings editor** — config is TOML-only, zero in-app settings. `M` 14. **Notifications & unread state** — only ephemeral toasts; no desktop notification, badge, or window-title status. `M` 15. **Queue editing / steer / send-now** — one FIFO with a "N queued" badge; no per-message edit, remove, or steer. `M` 16. **Subagent control** — child rows open a read-only transcript; no status, cancel, or message-child. `M` 17. **Plan card + plan approval** — ACP `plan` renders as one plain-text notice line. `S`–`M` 18. **Older-history paging / transcript windowing** — "Earlier messages aren't shown" with no load path. `M` 19. **PR & source-control actions** — no commit/push/PR, no PR badge/link, no publish/clone. `L` 20. **Provider/harness management** — TOML `command`+`args` only; no registry search, install, auth, or model catalog. `M` 21. **Right panel with tabs** (diff/files/PR/browser/terminal) — none; single-pane layout. `L`

# t3code → viz gap analysis

**Snapshot:** `pingdotgg/t3code`, branch `main`, tree `3ce2145864f1e8b822cc8dff9c8cfdf39d9e450b`, read 2026-11-18 via GitHub raw/API (no shell). Repo-relative paths; prefix `https://github.com/pingdotgg/t3code/blob/main/`.

## 1. t3code's product model (one paragraph)

A client/server ADE. `apps/web` is the entire UI (desktop is an Electron shell loading the same build). `apps/server` owns state in SQLite (`statev2.sqlite`), one event-sourced orchestration graph, one HTTP+WS RPC surface, one MCP endpoint for agents, and N provider adapters (native + ACP). The user-facing unit is a **thread** inside a **project**, optionally in a **worktree/branch**; threads live in a **sidebar work queue** (pinned/active/working/snoozed/settled), carry a **model + effort + permission mode**, stream a **turn timeline** with grouped activity and inline approvals, and expose **turn diffs**, **terminals**, **right-panel tabs**, **PR review**, and a **command palette** over everything.

## 4. P0/P1 notes (design detail)

**#26 Stop — `S`.** `AcpProcess.cancel` (`backend/src/agents/acp.ts:171-175`) already sends `session/cancel`, and `sessions.forget` kills the process, but no RPC reaches them. Add `conversation.abort {conversation}` → chat worker `abort` path (`agents/chat.ts:129-155` already settles queued submissions as `aborted`), plus a Rune button that replaces the send button while `Thread.live.busy`. ACP limit: `session/cancel` is a notification with no acknowledgement; the prompt resolves `cancelled`, which viz already maps to `unanswered`.

**#29/#30 Approvals — `M`.** Today `decide()` (`acp.ts:204-220`) answers every `request_permission` synchronously from a single global config value; the agent never waits on a human, and `reject` makes tool-heavy agents fail. Sketch: hold the `request_permission` promise, append a `viz.agent.permission` entry (`{requestId, toolCall, options[]}`), notify `conversation.view` watchers, and resolve from a new `conversation.answerPermission` RPC. Permission modes map onto option kinds (`allow_once|allow_always` vs `reject_*`); per-thread mode lives in a doc, with `Supervised` = ask for non-read kinds, `Auto-accept edits` = allow `edit` kinds, `Full` = allow all. ACP limit: ACP has **no reject-with-feedback** — `RequestPermissionResponse` is `selected(optionId)` or `cancelled`; t3's "type a reply to decline with feedback" is provider-native, so viz would need to cancel and send a follow-up prompt. ACP also has no "remember this tool" store; that must be viz-side.

**#27/#28 Model + effort — `M`.** `session/new` and `session/load` responses carry `configOptions` (model, thought level, mode); viz throws them away and never calls `session/set_config_option`. Persist them in `SessionDoc`, render pickers from `header.rs`, write the chosen ids into a `ConfigDoc` so reconnects re-apply. ACP limit: option ids/values are agent-defined (`claude-acp`, `codex-acp` differ); capability must be read from the advertised options, never hardcoded. Effort mapping to pi-durable's `thinking` doc is only for native chats.

**#23 Slash commands — `S`.** `available_commands_update` is stable v1 but has no case in `sessions.ts:255-310`. Store `{name, description, input}` in a doc, render a `/` popup over the composer, and send `/<name> <args>` as prompt text. ACP limit: there is no "execute command" request — the command runs only if it starts the message, exactly as t3 documents (`docs/user/composer.md`). `$skills` are not in ACP at all; they'd be a viz convention.

**#22 Attachments — `L`.** `conversation.submit` takes `text` only (`protocol.ts:63-71`). Add `attachments: [{id, name, mime, size, sha256}]`, a content-addressed store under `$STATE_DIRECTORY/attachments`, and ACP prompt blocks. ACP limit: only `text` and `resource_link` are baseline; `image` needs `promptCapabilities.image`, embedded text needs `embeddedContext`. Files therefore become `resource_link` + a copied path the agent can read — acceptable because ACP agents run with their own fs access. Rune needs drop/paste handling and a chip strip.

**#33/#32 Tool detail & diffs — `M`.** `apply()` keeps only `{id,title,kind,status}` (`model.ts:ToolRecord`); `thread.rs:330-340` therefore renders ACP tools with empty `arguments`/`output`. Persist `content[]`, `locations[]`, `rawInput`/`rawOutput` (cap sizes like `SUMMARY_CHARS`), and render `{type:"diff"}` with the diff view from #35 — this is the cheapest path to "see what the agent changed" and is a strict ACP win (the data is already on the wire).

**#35 Diff panel — `L`.** Requires a notion of "turn start". Options: (a) capture `git stash create`/a temp commit at each turn start and diff to HEAD (worktree-only semantics, like t3's file restore), or (b) accumulate ACP `tool_call` diffs per turn (no git needed, but misses shell-driven edits). Recommend (a) with (b) as the live preview. Server RPC returns per-file `{status, oldText, newText}`; Rune renders a file tree + unified hunks (no syntax highlighting initially). t3's `getTurnDiff`/`getFullThreadDiff` + `DiffWorkerPoolProvider` show the shape.

**#11/#12/#13 Thread lifecycle — `S`–`M`.** `TitleDoc` exists, but there is no rename method and `conversations.list` sorts by id (`server.ts:118-140`). Add one `ConversationMetaDoc` (title/pinned/archived/unread/order/snoozedUntil) so the sidebar can grow sections without more RPCs, plus `conversation.meta.set` and `conversation.delete`. Deletion semantics need a decision (pi-durable conversations are append-only) — a tombstone flag is cheapest and keeps transcripts.

**#14/#41 Search & palette — `M`.** No index exists. Cheapest: build an FTS5 table in `memory.sqlite` (already a viz-owned DB) from `sync.ts`-style walks of entries, keyed by `(conversation, entry)`. `conversations.search` returns hits; the palette lists commands + conversations + hits. Rune: one overlay element, `Cmd/Ctrl+K` via Rune key handling, arrow/Enter selection.

**#51 Paging — `M`.** `thread.rs` sets `earlier` from `view.before` but there is no request path. Add `conversation.entries {conversation, before, count}` returning the same shape `Thread::from_view` consumes, and prepend in `Desktop` on scroll-top (Rune needs scroll-position preservation).

**#10/#4/#5 Projects, worktrees, branch toolbar — `L`.** viz's `cwd` is fixed per chat at worker creation (`chat.ts:190-200`, `sessions.ts:107-122`). Introduce `ProjectDoc{root,name}` + `conversation.project`, resolve `cwd = worktree ?? project.root`, and add `git.*` RPCs. This is the single largest architectural gap for "ADE" parity, but it is additive: ACP sessions take an absolute `cwd`, so a worktree is just a different path. ACP limit: none — worktrees are outside the protocol; only re-creating the session with the new `cwd` is needed (and `session/load` rejects a different cwd on OpenCode, so a worktree change must start a fresh session).

**#36 Checkpoints — `L`.** pi-durable gives transcript-level checkpoints; file revert must be git. Restrict to worktrees and refuse when the directory is shared (t3 does the same and documents why). "Edit from here" = truncate/fork the conversation (pi-durable `fork: "initial"` docs already exist) + return the prompt to the composer.

**#38 Terminal — `L`.** The highest-effort P1. Bun lacks `openpty`; options are a small Rust sidecar (`portable-pty`) or `node-pty` under Bun. The client needs a VT emulator; Rune has none. ACP terminals are not the answer: `terminal/*` is client-side _execution_ with no PTY semantics, and ACP v2 removes it. t3 deliberately used `node-pty` server-side with a WASM renderer.

**#44 Notifications — `M`.** Rune has a `dbus` feature (TODO mentions it). Fire on turn terminal state when the window is unfocused; add unread (#13) and a window-title status mirroring t3's "Working / Needs approval / Needs your input".

**#43/#42 Settings + keybindings — `M`.** viz's config is layered TOML with a Rust and a TS loader that must stay in sync (`AGENTS.md`). A settings UI should write `config.d/*.toml` drop-ins (already in TODO) and call a reload RPC; keybindings belong in the same file as `[keys]`. t3's `keybindings.json` + `when` grammar is over-engineered for viz — start with a fixed command set and rebindable chords.

**#52 Provider management — `M`.** `harnesses.list` can spawn each configured runner, `initialize`, and report `agentCapabilities` + `configOptions` (models) — this also feeds #27 and turns viz's static TOML into a discoverable picker.

**#19/#18 Subagents — `M`.** viz already nests child rows and marks running ones (`sidebar.rs:120-160`), but `Thread.live.busy` is only known for the watched conversation (TODO acknowledges this). Add per-conversation status to `conversations.list` (or a `conversations.status` notification), a child-status entry from `report_progress`, and cancel/message via the orchestrator toolkit (viz's `report_progress` is currently the only MCP tool; t3's `t3_thread_*` set is the model to copy).
